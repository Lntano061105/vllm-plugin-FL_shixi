# Ascend NPU Op Benchmarks

Throughput benchmarks for vllm-plugin-FL on Ascend 910B3, used to produce the
MoE Init Routing Custom intake baselines (Qwen3.6-27B / 35B-A3B, TP=4).

## Environment

| Item | Value |
|---|---|
| Device | Ascend 910B3, TP=4 (baselines on devices `0,1,2,3`, 27B graph on `4,5,6,7`) |
| CANN | 9.0.0 |
| Python | 3.11.14 (`/usr/local/python3.11.14/bin/python3`) |
| vLLM | 0.20.2, torch 2.11.0 |
| Plugin | vllm-plugin-FL, built in-tree: `VLLM_VENDOR=ascend pip install -e . --no-build-isolation` |
| Custom ops | `source vllm_fl/_cann_ops_custom/vendors/custom_transformer/bin/set_env.bash` before serving |

## Files

| File | Purpose |
|---|---|
| `benchmark_script_fl.sh` | Benchmark entry point: starts an OpenAI-compatible server, runs `vllm bench serve`, collects results and writes `request_benchmark_results.txt` into the RUN_DIR |
| `run_command.sh` | The four exact commands used for the archived baselines |
| `analysis.py` | Aggregates every `request_benchmark_results.txt` under `--result-root` into one CSV + Markdown table (`benchmark_summary.csv` / `.md`) |
| `benchmark_summary_20260915.csv` | The aggregated CSV of the four archived 09-15 baselines (one row per case) |
| `benchmark_summary_20260915.md` | Same data as a Markdown table |

## Run

`FL_REPO_PATH` must point at the plugin checkout that supplies the custom ops.
The archived baselines used `/workspace/vllm-plugin-FL.bak.20260817`; export it
once instead of editing the commands:

```bash
export FL_REPO_PATH=/workspace/vllm-plugin-FL.bak.20260817

# 1) start + measure one configuration (writes to $RESULT_ROOT/<RUN_NAME>/)
bash benchmarks/ops/ascend/benchmark_script_fl.sh \
  --model-path /models/Qwen3.6-27B --model-name qwen3.6 --model-tag qwen3.6-27b \
  --mode graph --cases 1024,1024,128 --concurrency 64 \
  --max-num-seqs 64 --max-model-len 8192 --tp 4 --gmem 0.6 \
  --devices 0,1,2,3 --port 8113 --no-bench-profile --skip-analyse \
  --package none --run-label shixi_baseline --fl-repo-path ${FL_REPO_PATH}

# 2) aggregate all runs
python3 benchmarks/ops/ascend/analysis.py --result-root /workspace/results
# or only the four archived runs:
python3 benchmarks/ops/ascend/analysis.py \
  --run-dirs /workspace/results/atp_qwen3.6-27b_fl_graph_chunked_shixi_baseline_pw_tp4_gmem0.6_20260915_115604 \
             /workspace/results/atp_qwen3.6-35b-a3b_fl_graph_chunked_shixi_baseline_pw_tp4_gmem0.6_20260911_102049 \
             /workspace/results/atp_qwen3.6-27b_fl_enforce_eager_chunked_shixi_baseline_pw_tp4_gmem0.6_20260911_103545 \
             /workspace/results/atp_qwen3.6-35b-a3b_fl_enforce_eager_chunked_shixi_baseline_pw_tp4_gmem0.6_20260911_105227 \
  --csv benchmark_summary.csv --md benchmark_summary.md
```

Key arguments: `--model-path` / `--mode graph|eager` / `--cases I,O,NP` /
`--concurrency` / `--tp` / `--gmem` / `--devices` / `--port` /
`--fl-repo-path` / `--result-root` (default `/workspace/results`).
`--cudagraph-mode` selects the graph mode variant (FULL /
FULL_DECODE_ONLY / PIECEWISE); the archived baselines used PIECEWISE.

`analysis.py` reads the `Serving Benchmark Result` blocks and emits
`benchmark_summary.csv` / `benchmark_summary.md` with one row per case:
run, model, mode, case, successful/failed requests, Output/Total token
throughput, Mean TTFT, Mean/Median TPOT, Mean ITL.

## Reproduction evidence

`benchmark_summary_20260915.csv` was regenerated by running `analysis.py` on the
four `request_benchmark_results.txt` files above (all under `/workspace/results/`);
the resulting `output_tok_s` values are exactly 490.34 / 326.11 / 293.21 / 268.38,
matching the table and the PR description. The CSV also carries the `run` column
(full RUN_DIR name) and the `time` column (benchmark wall-clock), so every number
is traceable to a directory on the machine.

Notes:
- `benchmark_results/*.csv` in the repository root are the raw client CSVs of an
  older 07-18 batch with no model/mode/time columns; they are **not** the source
  of the four numbers above. The 09-15 batch (parsed here) is authoritative.
- Mean vs Median TPOT differ (e.g. 27B graph: 121.33 vs 125.48 ms); reports should
  state which statistic is quoted. The tables above quote **Mean**.
- 27B graph was re-run on 09-15 on devices `4,5,6,7` after the 09-11 attempt on
  `0,1,2,3` hit a KV-cache OOM during engine warm-up (rc=1, no numbers); software
  stack, model, parameters and plugin path were unchanged.
